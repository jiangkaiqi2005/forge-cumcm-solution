# forge-cumcm-solution

> 一个面向 AI Agent 的 **CUMCM（全国大学生数学建模竞赛，国赛）全流程 Skill**：把「审题建模 → 代码求解与验证 → 论文写作与提交审查」三个阶段的全部质量要求，固化为一套可执行、可检查、可追溯的指令体系，驱动 Agent 端到端产出接近提交级的竞赛成果。

## 项目背景

国赛优秀论文的稳定特征不是「模型越多越好」，而是一条完整的证据链：

> **准确理解题目 → 建立统一机制 → 选择匹配算法 → 给出可执行结果 → 建立可信证据 → 用评委能快速验证的方式呈现。**

但让 AI Agent 独立完成这样的全流程，常见的失败模式是：堆砌算法名词、编造运行结果、数据泄漏、摘要与正文数字冲突、用截图制造完成感。本 Skill 通过**多路独立方案竞选、八席盲审评分与交付安全网门禁**等机制，把上述失败模式逐条变成可检测、可阻塞的硬约束。

本项目以《国赛优秀数学建模论文特征与模仿指南-综合版》v1.0（基于 2023—2025 年 15 道国赛题目与 37 篇优秀论文的六轮专项分析）为唯一权威方法论来源，并将其操作化为分阶段的执行合同与评审量表。

## 核心特性

- **三阶段流水线**：阶段一审题与模型、阶段二求解与结果证据、阶段三论文与提交，逐级冻结、逐级验收，前序不过不开工。
- **八路方案竞选**：阶段一至少 8 个互相隔离的方案 Agent 独立完成「独立思考 → 论文检索 → 本题融合」，再由八席评委盲评全部候选选出胜者，禁止一个 Agent 伪装多份方案。
- **八席盲审评审**：每阶段恰好 8 个必需专业角色（可按题型风险动态增席），独立盲审、封存评分、交叉质询；五项各 20 分、总分 100，任一席未满分即候选失效、换全新评委完整重评。
- **单一事实链**：所有关键主张标记 `FACT / ASSUMPTION / COMPUTED / VERIFIED / BLOCKED` 状态，题面 → 模型 → 代码 → 输出 → 论文主张可双向追踪；证据内容变化后旧评分自动失效。
- **交付安全网门禁**：Python 脚本只检查阶段产物齐全、八席评审报告到齐、最终 PDF 结构可读和官方赛题/数据未被改动；不判断数学质量——专业判断归执行者与八席评委。
- **诚实阻塞**：缺少会改变结论的题目、数据、规则、模板、运行环境或独立评审能力时，只能报告 `BLOCKED`，禁止虚构满分或包装未通过版本。

## 使用方式

本仓库是一个 Skill 包（纯 Markdown 指令 + Python 门禁脚本），无运行时依赖，门禁脚本仅需 Python 3。

**全流程作答**：将本 Skill 提供给支持 SKILL.md 规范的 Agent，给出赛题与附件即可。默认每个阶段通过八席满分评审后暂停确认；明确要求端到端运行时连续推进。

**阶段续作 / 已有论文审查**：Skill 内建路由——续作先核验前序成果；审查已有论文从阶段三开始，但模型或数字断链必须回退阶段一或二。

**机械检查命令**：

```bash
# 阶段门禁：产物齐全、八席评审报告到齐、PDF 可读、官方材料未改动
python scripts/check_stage.py --manifest <阶段工作目录>/stage-manifest.json --stage <1|2|3> \
    --trusted-inputs <官方材料校验文件>
```

脚本通过只是必要条件，不能替代阶段八席的专业判断。

## 每阶段执行循环

1. **读当前材料与指南**——按追溯表只加载相关章节，不整份塞入上下文；
2. **建立本题执行合同**——把指南特征转成具体动作、产物、证据和可判定验收条件；
3. **高质量执行**——完成本阶段全部产物并主动做基线、反例与独立验证；
4. **执行者预审与冻结**——按八席量表逐席自查，全部有证据才冻结候选版本；
5. **八席独立评审与迭代**——未参与编写的全新评委盲审，未满分即换人重评；
6. **交付或阻塞**——全席 100/100、无否决、机械检查通过才交付，否则只报告 `BLOCKED`。

## 绝对禁止

- 编造数据、参数来源、文献、运行结果、图表、评审身份或验证；
- 漏答小问、混用对象 / 场景 / 单位 / 分母，或让各处数字冲突；
- 把算法名当模型、把软件名当创新、为复杂而复杂；
- 无证明地声称全局最优、不可行、鲁棒、因果或普适；
- 用全数据预处理、特征选择或调参造成数据泄漏；
- 事后放宽约束容差、挑幸运随机种子或只报告最好一次；
- 用截图、装饰性 3D、彩虹色和空泛形容词制造完成感；
- 省略当年模板、匿名、文件命名、支撑材料或 AI 使用披露要求。
